# AutoKey 官網整站改版：完整需求確認稿

版本：R1｜日期：2026-10-22｜狀態：confirmed

## 可直接沿用的工作指示

以 AI 開發團隊模式，在 `D:\AutoKey_Site` 重新設計 AutoKey 官方網站。這是既有正式網站的整站改版，需完成視覺設計、互動動畫、三語文案、前端實作及實際瀏覽器驗收。

1. **重新設計整個官網。** 重新安排首屏、產品功能、應用情境、操作說明、相容性、常見問題與取得資訊的閱讀順序、版面及手機呈現。沿用 AutoKey 標誌與既有石墨黑／薄荷綠品牌；整站設計不只換色或調整幾張卡片。先提供可操作、已實際渲染的完整 HTML 設計稿，涵蓋所有章節、手機版及必要互動狀態，經 PM 核對需求後交使用者確認，再套用至正式網站。
2. **整個網站要有動畫互動感。** 首屏、章節進場、功能展示、應用情境和操作回饋需有一致的動態設計。以動畫幫助訪客看懂按鍵設定與畫面結果的關係。互動示範能開始、停止、重播；切換情境、語言或離開分頁時須正確停止。保留鍵盤與觸控操作、清楚焦點、手機閱讀，以及減少動態效果的替代呈現。
3. **視需要製作遊戲應用示意影片或動畫。** 優先做能看懂「按鍵輸入 → 遊戲內動作 → 執行節奏」的具體情境。如果頁內互動動畫已能清楚說明，不為了影片額外增加載入負擔；若影片更適合，則交付可播放檔案、必要靜態封面與可維護來源。無真實實測素材時，清楚標為情境示意，不冒充實機錄影或特定遊戲相容性證明。效果、按鍵時序與設定必須符合已查證的桌面程式能力。
4. **重新審視所有畫面文案，去除 AI 味。** 範圍包含導覽、標題、內文、按鈕、操作狀態、提示、FAQ、頁尾、SEO 與輔助標籤。改用具體、自然的介紹，刪除空泛形容、口號、重複解釋與工程工作紀錄語氣；保留必要限制與已查證事實。既有繁體中文、English、简体中文同步更新，三語不能混用、漏譯或讓長文字破版。
5. **保留既有可用行為與專案邊界。** 保留語言偵測與手動選擇、無 JavaScript 時可讀內容、有效導覽與真實連結。網站示範僅在頁內運作，不控制作業系統或實際遊戲、不攔截全域快捷鍵、不新增個資收集或追蹤。沿用靜態 HTML／CSS／JavaScript 與本站獨立建置；需要新增動畫依賴時，先確認既有原生能力是否足夠。
6. **以產品事實決定對外描述。** 核對桌面程式目前可證明的連點、長壓、群組、快捷鍵、視窗相容性與取得狀態。不把同時起算的群組描述成依序連招；不把尚未驗收的 Steam／Cloud、未測遊戲相容性或下載供應寫成已完成。遊戲應用情境保留適用條件，但以訪客讀得懂的短句說明。
7. **驗收與交付。** 實際操作桌面及手機網站，檢查三語、完整旅程、動畫停止與重播、快速重複操作、鍵盤、減少動態、縮放、文字對比、載入與 console。執行與改動有關的既有檢查、語系測試、建置及邊界驗證；提供預覽、截圖、結果和未完成項目。更新必要設計／交付文件，驗證後提交本站本機 Git。

## 工作順序與責任

- PM 整理完整需求並核對產品事實；本文件確認後才展開需求細分及設計。
- UI/UX 負責整站 HTML、資訊層級、動態規格、手機呈現及素材用途；內容角色負責三語改寫與事實回讀。
- 如需獨立影片，由動畫角色負責分鏡、素材來源、製作及播放驗證。
- Frontend 依使用者確認的設計實作，QA 以正式頁面及對應設計驗收。使用 `ai-dev-team-orchestrator` 的既有流程，避免重複詢問已確認事項。
- 本次需求授權本機改版與驗證；GitHub push、替換線上正式快照或變更託管設定不由「整站重新設計」推定。
