## 使用者故事

- US-R1：第一次造訪的人能看懂 AutoKey 適用於 Windows 的鍵盤／滑鼠連點與長壓，以及如何啟停。
- US-R2：想用在重複操作的人能試看不同按鍵節奏如何影響場景，並自行停止與再次執行。
- US-R3：評估安裝的人能了解設定步驟、群組／滑鼠／相容性限制、語言與取得狀態。
- US-R4：使用不同語言或裝置的人能閱讀同樣完整資訊，使用鍵盤與減少動態偏好操作。
- US-R5：網站維護者能沿用獨立靜態建置、素材與清楚的驗證紀錄更新網站。

## 條件式功能需求

* **條件 FR-R1**：訪客開啟首頁。
  * **行為**：呈現產品名稱、Windows 平台、鍵盤／滑鼠左右鍵用途、可自訂快捷鍵，以及可操作示意入口；整站包含首屏、功能、情境、設定步驟、相容性、FAQ、取得狀態及頁尾。
* **條件 FR-R2**：訪客點選首屏播放。
  * **行為**：播放三次「E 長壓 1 秒、釋放後等待 1 秒」的原創場景動畫，最多 6 秒後停止；可中途停止及重播。明示網頁情境示意，不是實機錄影。
* **條件 FR-R3**：訪客選擇應用情境。
  * **行為**：三個對等情境為長壓互動、滑鼠連點、定時翻頁；顯示按鍵、模式、時間、場景結果、條件。長壓為按住 1 秒／等待 1 秒；滑鼠左鍵為每 0.5 秒點按；PageDown 為每 2 秒點按。滑鼠位置固定，不暗示自動移動游標。
* **條件 FR-R4**：訪客執行一次、循環、停止或重播。
  * **行為**：鍵帽、場景動作、計時階段與次數保持一致。單次完成可再開始；循環保留停止入口。執行時單次按鈕停用且狀態有說明。重新啟動歸零，停止保留次數並釋放鍵帽；不能殘留延遲回呼。
* **條件 FR-R5**：切換情境／語言、離開分頁或離開頁面。
  * **行為**：所有播放停止並取消排程；回到分頁不自動開始。切換語言保留目前情境、FAQ 展開、位置與焦點，並以新語言顯示停止狀態。
* **條件 FR-R6**：訪客閱讀功能、步驟、相容性與取得資訊。
  * **行為**：補齊鍵盤／左右滑鼠、單鍵及快捷鍵錄製、群組一次／循環、本機保存、31 種桌面介面語言。錄製不是動作序列；群組同時起算，不支援依序連招。背景接收依目標而定；不保證前景或管理員就相容。首發不提供 Cloud；Steam 發布資訊待公告，不設假下載。
* **條件 FR-R7**：訪客切換繁中、英文或簡中。
  * **行為**：全頁正文、SEO、輔助標籤、動態回饋同步切換。沿用有效手選優先、再依瀏覽器語言、無匹配英文的規則。只存語言；storage 受限不影響當次使用，提示不能記住選擇。
* **條件 FR-R8**：鍵盤／觸控、手機 320px、200% 放大或減少動態偏好。
  * **行為**：閱讀與操作完整、無水平溢出、焦點清楚、操作目標至少 44px。頁籤支援方向／Home／End；FAQ 原生開合。減少動態停用裝飾位移，保留示範文字與離散狀態。無 JS 保留繁中全文及各案例說明，隱藏無效控制。
* **條件 FR-R9**：訪客捲動或聚焦操作。
  * **行為**：首屏構圖進場、章節短距離進場、鍵帽回饋、功能微動畫與 FAQ 狀態具一致時間。自動裝飾動畫單次完成，不無限播放；畫面文字在動畫過程保持可讀。不攔截全域按鍵、不送出系統輸入、不收集按鍵。
* **條件 FR-R10**：設計／正式網站交付。
  * **行為**：設計有實際渲染、所有章節與狀態、可見流程圖、素材用途、PM 覆蓋檢查及使用者版本確認。工程沿用該版本與素材，QA 操作正式旅程；只在實際完成的階段宣稱驗收。執行既有語系、語法、建置與邊界檢查，相關修改提交本站本機 Git。

## 分階段工作與驗證

1. PM：記錄 R1 批准、檢查 CEO 報告、建立 P1 及 D1 設計規格。驗證需求原項完整覆蓋、路徑與事實；本機提交規劃階段。
2. UI/UX／內容：依 D1 製作整站 HTML、原創 SVG、CSS、互動腳本與三語，提供 review 流程圖。先以瀏覽器操作檢查需求，再修具體缺陷；視覺修改共用 `visual-review.md` 的最多三次預算。瀏覽器驗證是設計階段主要檢查，不為可逆版面寫鏡像測試。
3. QA／PM：在 1440、1280、768、390、320 寬度與三語驗證排版；操作首屏播放、3 情境單次／循環／停止、切換中止、隱藏分頁、鍵盤、FAQ、語言保存／受限、無 JS、減少動態。儲存 `output/playwright/redesign-v1-*`，檢查對比與資源。獨立檢查並記錄 D1 PM coverage pass 後，提交設計及交接、提供使用者確認。正式驗收此時仍 pending。
4. Frontend（需 D1 使用者確認）：把已確認設計整合正式 `public/` 與根 locales；沿用既有語言 resolver，先驗證需要新增的取消／時序行為再修改；同步設計對照、README。
5. UI/UX＋QA：比較確認稿與正式畫面，跑完整相關旅程及 `npm.cmd run check`、`test:localization`、`build`、`test:boundaries`。完成後本機 commit；不推送、不替換正式快照。未完成檢查必須明列。
