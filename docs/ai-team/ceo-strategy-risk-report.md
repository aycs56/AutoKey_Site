## 一、市場與實際受眾

主要受眾是需要重複按鍵、滑鼠點擊或持續按住的 Windows 使用者，包括日常重複操作，以及明確允許自動化的遊戲環境。既有需求已確認要解釋這些情境；尚未證明哪一群使用者最多。手機訪客是閱讀與評估受眾，不應讓網頁示範暗示手機可執行桌面自動化。

| 現有替代方式／證據 | 可解決的問題 | AutoKey 應說清楚的差異與限制 |
| --- | --- | --- |
| 手動重複操作、目標程式本身的操作設定；屬合理替代假設 | 不另裝工具，沿用原有流程 | 說明設定連點／長壓與自訂啟停的用途；不捏造省時數字，也不保證所有程式接受輸入 |
| Microsoft Power Automate for desktop 官方滑鼠／鍵盤動作 [S1] | 送出按鍵、點擊及滑鼠移動，並可放入桌面流程 | 本站聚焦按鍵群組、連點／長壓和啟停設定；AutoKey 不提供本案未證明的游標移動、完整流程編排或順序巨集。工具能力有交集，差異是使用範圍與呈現重點，非獨家能力 |

需求證據限於已確認改版需求、桌面既有功能，以及替代工具存在；它們能支持「需要清楚解釋操作」的方向，不能證明市場需求量。建議以無追蹤的人工任務驗收檢查理解：讀者能指出連點與長壓差異、如何啟停，以及示範與真實相容性的界線。若日後有自願訪談，再調整受眾排序。

## 二、策略、營運與方案選擇

價值主張建議為「設定鍵盤或滑鼠的連點與長壓，用自己的快捷鍵開始、停止」。首頁先展示輸入、執行節奏與場景結果，再帶入設定方式、相容性與取得資訊。此方向保留全部章節及三語，不以重複口號或未來功能補足內容。

本輪採可互動的自製原創場景，將按鍵亮起、連續動作與長壓結果對齊；清楚標為網頁情境示意。這是待 HTML 設計驗證的可行方案，不是已完成證明。只有原生示範無法清楚傳達必要情境時，才重新評估影片；屆時須有可播放檔案、封面、可維護來源與權利紀錄。

一年相對維護成本以下列共同條件比較：同樣涵蓋整站動態、三語、手機、鍵盤、停止／重播、減少動態及無 JS 可讀內容；不估金額。首次製作工時與持續成本分開看，且成本不凌駕必要行為與權利要求。

| 方案／依據 | 需求涵蓋與風險處理 | 一次投入與一年維護成本 | 決策 |
| --- | --- | --- | --- |
| 靜態 HTML＋原生 CSS／SVG／WAAPI；沿用現有建置 | 可保留完整互動；狀態須集中管理，動態不支援時退回文字／靜態圖；依 [S2][S3] 提供減少動態與停止控制 | 初次需製作場景與狀態邏輯；持續成本相對低：無新增 runtime 套件／訂閱，沿用語系、託管與回復方式。仍須維護瀏覽器相容性、Node／Caddy、三語回歸與備份 | 建議採用；在目前範圍內，較少新增升級、授權與交接負擔 |
| 新前端框架＋動畫依賴 | 同樣可滿足；需保留靜態輸出或無 JS 路徑，並重建既有行為測試；並未消除動態／翻譯問題 | 初次有遷移及工具鏈投入；持續成本相對中：新增版本、相依套件／授權檢查、框架技能、建置故障與回退測試。共用組件可能降低未來多頁複雜度，但本輪尚無此規模證據 | 本輪不選；出現跨頁狀態或大量共用複雜組件時再比較 |
| 影片為主＋必要 HTML 互動 | 單靠影片不能涵蓋設定選擇、開始／停止與操作回饋，仍須網站互動；另需播放控制、文字等值內容及權利查核 | 初次需分鏡、製作、編碼；持續成本相對中高：功能變更重製、三語字幕／畫面、封面、媒體載入及播放器回歸；製作來源與技能需交接 | 本輪不作主方案；必要時作補充，避免把條件式影片要求變成固定負擔 |

維護分工：PM／內容角色更新產品事實與三語；UI／Frontend 保管原創素材、場景與動態狀態；QA 回歸旅程；網站擁有者維護現有託管。本站目前是產品介紹與評估入口，沒有本輪定價、收款或營收指標。可持續性來自單一事實來源、可編輯場景和既有靜態部署，不依賴新增服務。

## 三、主要平台風險

下列可能性／影響為本案定性判斷，不是事故機率；每項保留可執行的退路與責任人。

| 風險與判斷 | 規避／緩解、退路與責任 |
| --- | --- |
| 動畫造成不適、注意力負擔；可能性中、影響高，全站新增動態擴大暴露 | 尊重 `prefers-reduced-motion`；裝飾動畫不無限播放。自動開始、超過五秒且與其他內容並列的動態須可暫停／停止／隱藏 [S2][S3]。示範以明確操作啟動、可停止／重播；退路為靜態流程。UI／Frontend 實作、QA 驗證；不因此宣稱全站 WCAG 認證 |
| 快速操作、切語言／情境、隱藏分頁留下計時器或錯誤狀態；可能性中、影響中 | 共用取消與重設流程；檢查連點、切換、重播、分頁隱藏後恢復。僅頁內事件，不攔截全域快捷鍵或 F12；失敗保留文字說明並停示範。Frontend／QA 負責 |
| 手機效能、瀏覽器 API 或 localStorage 受限；可能性中、影響中 | 優先 transform／opacity、小型 SVG、功能偵測與儲存例外處理；減少動態和無 JS 下仍可讀。QA 實測桌面／手機尺寸及代表性瀏覽器；不以自動化單一瀏覽器等同全部裝置支援 |
| 託管中斷、共用 Caddy／Node 更新、部署誤觸桌面 repo；可能性低至中、影響高 | 沿用網站獨立建置、快照、健康檢查與既有回復流程；本輪不變更託管。來源、靜態資產可移轉，無新增服務綁定；正式交付前按授權驗證。網站維運者保管復原程序，Frontend 守 repo 邊界 |
| Steam 供應狀態或桌面能力變動導致錯誤承諾；可能性中、影響高 | Build 上傳不等於發布，官方流程另有審查與發布操作 [S4]。PM 使用「Steam 發布資訊待公告」等已知狀態；有效商店／下載證據取得前不放假 CTA。產品版本更新即重查，退路為資訊文字而非失效連結 |

## 四、法律、IP 與隱私風險

法域以台灣網站經營及全球可讀官網為本輪評估基礎；Steam／第三方內容另受其條款影響。三語本身不等於已完成所有地區法遵。下表是設計風險處理，不是個案法律意見或零侵權保證。

| 項目與證據 | 本案界線、處理與剩餘風險 |
| --- | --- |
| 遊戲畫面、角色、地圖、音樂及商用素材著作權 [S7] | 本輪自製通用原創 SVG／CSS 場景，不搬用特定遊戲美術、商標、音樂、截圖或臨摹可辨識角色；保留來源與製作紀錄。自行製作不能單獨證明無侵權，UI／內容角色仍須檢查實質近似與第三方成分。日後真遊戲影片須先查授權及使用條款，有疑義交權利人或合格法律專業確認；標示「示意」不能取代授權 |
| Steam 商標與內容真實性 [S5][S6] | 優先文字交代 Steam 狀態；若使用標誌，限官方核准圖稿、遵循標示規範，不暗示 Valve 背書。Steam 商店規範要求列示功能與當前可交付內容相符；該規範直接管商店，本官網採相同事實標準，不把自製場景送作實機證明。PM 負責文案、UI 負責素材 |
| 隱私與資料處理 [S8] | 不設登入、付款、表單、追蹤、外部字型或第三方嵌入；只存本站語言偏好，不記錄按鍵內容。付款資料義務在本輪無處理活動，不能擴大成「網站一律不涉及個資」。伺服器存取紀錄可能含可識別資訊，既有日誌範圍尚未審查；維運者在任何「完全不收集資料」對外宣稱前查核用途、保存與存取權。若新增資料蒐集，先重評個資法與目的地要求 |
| 軟體／素材授權、遊戲條款及消費者資訊 | 延用品牌資產仍應保留來源；若新增套件、字型或音效，先留授權與必要聲明，本輪以無新增依賴／外部字型降低負擔。遊戲自動化須以目標環境允許為前提，不承諾反作弊通用相容或不封號。未證明功能、下載供應、評價與銷售數字不得寫成事實；本輪不辦交易，將來新增售價／購買流程再查交易與退款義務。PM／網站擁有者負責 |

## PM 採用條件與後續查核

- 建議將本報告 R1 映射至需求的產品事實、三語、原創示意、動態取消、無障礙、隱私與交付條件；PM 查核後才記錄報告可用性與正式計畫決策。
- HTML 設計須讓未參與實作的評閱者完成三項理解任務；每個場景可用滑鼠／觸控與鍵盤開始、停止、重播，切換語言／情境／分頁後無殘留動作。三語、手機、縮放與減少動態均須實際渲染；這些是待驗收目標，尚未通過。

- 剩餘不確定性為受眾排序、實際理解成效、正式託管日誌與公開取得狀態；前兩項可在設計評閱驗證，後兩項限制相關對外宣稱，無須藉此擴大本輪網站功能。
