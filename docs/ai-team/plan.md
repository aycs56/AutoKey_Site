# AutoKey 官方網站需求與製作計畫

2026-09-25；profile web + docs；standard。網站本機製作，獨立 Git；不公開部署。

## 使用者目標

- US-S1：訪客能快速理解 Windows AutoKey 的連點、長壓、群組與自訂快捷鍵用途。
- US-S2：訪客能透過日常工作、遊戲重複操作／掛機、格鬥指令拆解，辨識現有能力及限制。
- US-S3：訪客能在網頁安全試玩按鍵節奏，開始、停止與切換範例；示意不操作系統。
- US-S4：維護者能在獨立 repository 建置官網，未來推送 AutoKey_Site，不混進 AutoKey 程式 repository。

## 條件與行為

- FR-S1：當訪客開首頁，顯示清楚產品名稱、Windows 平台、主要用途、可操作示意入口；品牌沿用既有 icon／石墨／薄荷綠。
- FR-S2：當選擇應用情境，顯示該情境範例、按鍵模式／時間、預期結果與限制。日常工作與允許自動化的遊戲環境為現有機制範例；複雜連招需明列尚未支援按順序輸出。
- FR-S3：當開始互動示範，頁內鍵帽與節奏回饋同步變化，可停止；當切換情境或分頁隱藏，自動停止；單次模式完成後可再次執行。不得攔截瀏覽器快捷鍵或傳送系統按鍵。所有示意固定範例，不是正式設定編輯器。
- FR-S4：當從功能、情境、FAQ 導航，抵達對應章節；窄螢幕無水平溢出，鍵盤可達全部互動，焦點清楚，減少動態設定生效。按鈕／連結可觸區至少 44px。
- FR-S5：當閱讀下載／Steam 狀態，明列尚未上架與 Cloud 尚待驗收，不提供失效或假成功按鈕。31 語系是桌面介面能力，網站提供英文、繁中與簡中。
- FR-S6：當本機建置，產出獨立靜態網站，不讀桌面使用者設定或包含 desktop 源碼；Git main 與 origin 指定 AutoKey_Site，僅本機提交。

## 設計方向與範圍

單頁正式網站：主視覺與可操作按鍵示意 → 現有功能 → 三種應用情境 → 開始使用的三步 → FAQ／取得狀態。主要行動為「體驗按鍵節奏」，未上架階段不放無效下載。

標誌沿用桌面資產；主視覺使用可縮放鍵帽／線路／節奏 CSS 與產品縮略介面，標明示意；不製造遊戲畫面或產品相容性背書。使用系統繁中字體與有辨識性的英文字級，避免外部字型依賴。網站不包含帳戶、付費、訂閱名單或後台。

## 角色與階段

- Root PM／Lead：需求、治理、獨立 Git／建置、內容誠實性、整合驗收。
- UI/UX：在工程前完成 ui-ux-spec.md，含 token、完整頁面／互動狀態、flow、组件來源與資產用途。
- Frontend：正式網站 HTML/CSS/JS；依設計交付，無額外 prototype。
- QA：瀏覽器正式旅程、桌面與手機截圖、可及性、非支援功能提示、console/network；與桌面專案 Git 邊界核對。

## 完成條件

### 三語追加（2026-09-25）

本地化簡報：範圍為官網閱讀與互動示意，採英文（跨地區）、繁中（含 TW/HK/MO 偏好）與簡中（含 CN/SG 偏好）；語言推斷只服務顯示，不定位訪客或限定市場。沿用原產品、品牌及相容性表述，不新增平台、售價、法律或地區供應承諾，無需新平台政策判定。PM／Lead 負責解析與網站整合，獨立翻譯角色人工整理英文／簡中文案並唯讀審查，QA 以正式網站驗證三語旅程。低風險 web 變更，僅新增本站語言偏好，沒有後端或桌面設定異動。

- US-S5／FR-S7：訪客可以在頂部原生語言選單切換 English、繁體中文、简体中文；所有可讀文案、title／meta description、輔助標籤、示範按鈕及動態狀態同步翻譯。品牌與按鍵代碼不翻譯。
- FR-S8：有有效手選偏好時優先使用；否則按 navigator.languages 順序選支援語言。zh-Hant或TW/HK/MO為繁中，zh-Hans或CN/SG及zh為簡中，en為英文；沒有對應則英文。無效／禁止 storage 不阻擋網站，當次手選仍有效。
- FR-S9：切換保留情境、FAQ展開、頁面位置與焦點；停止正在執行的示範並以新語言顯示停止原因。重新載入恢復語言；不自動開始示範。
- FR-S10：沿用单頁與品牌，以本機翻譯包同步載入，不新增遠端依賴。JS停用時保留原有繁中靜態全文與提示，選單不顯示失效控制。翻譯採來源字串 msgid，補充完整性測試；不使用機器批量轉字代替英文／簡中文案審校。
- 驗收：locale偵測／無效storage、三語全頁與三情境／動態狀態、持久化、切換中斷、desktop／320／390窄版、無未翻譯正文／截字；只提交網站本機Git，不push。

本機可預覽、build 成功、頁面操作與視覺通過，Git 已建立且包含驗證後的 local commit。網站未推送／未部署要清楚報告。Steam 上架仍屬桌面專案後續流程，不能視為本網站完成的一部分。
